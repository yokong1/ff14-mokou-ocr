# ff14 mokou ocr

FF14「魔光键影」活动的屏幕文字识别与输入辅助工具。当前版本：**0.9.2**。

沿用原版已经验证的流程：识别怪物名字 → 匹配词库 → Enter 激活输入框 → Unicode 输入汉字 → Enter 发送 → 观察目标变化。正常优先使用 Unicode 直输，保留原有失败重试与兼容回退。

## 运行环境

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows 10 / 11，64 位 |
| Python | **Python 3.x（64 位，包含 Tcl/Tk）** |
| Python 安装选项 | 使用完整安装器，保留 **Tcl/Tk（tcl/tk and IDLE）**；建议勾选 Add Python to PATH |
| 文字识别 | Windows 自带 OCR，需要系统具备简体中文 OCR 语言组件 |
| 游戏显示 | **建议窗口化或无边框窗口化**，并保持游戏画面可见 |
| 启动入口 | **推荐双击「管理员启动.bat」**，在系统权限提示中选择「是」 |

无需执行 `pip install`，无需安装 Pillow 等第三方 Python 包。普通使用直接运行随项目提供的 OCR 程序，无需自行编译或安装 Windows SDK。

## 下载与启动

1. 从 [Releases](https://github.com/yokong1/ff14-mokou-ocr/releases) 下载版本压缩包，或在仓库选择 **Code → Download ZIP**。
2. **完整解压整个文件夹**，保留 `app.py`、`core`、`bin`、`launcher.ps1`、词库和两个启动批处理文件。不要只下载单个 Python 文件，也不要直接在压缩包内运行。
3. 安装完整的 Python 3.x（64 位，包含 Tcl/Tk）。
4. 将游戏设为窗口化或无边框窗口化，进入需要识别的活动画面。
5. 双击 **「管理员启动.bat」**。也保留普通权限入口「启动.bat」，供不需要提权的环境使用。
6. 确认工具标题显示 **ff14 mokou ocr · 0.9.2**。

## 使用方法

1. 点击「刷新窗口」，在目标窗口列表中选择游戏。最小化窗口可以出现在列表中，但开始识别前需要恢复显示。
2. 使用「拖拽框选区域」，框住**怪物名字可能出现的完整范围**，尽量排除无关画面。
3. 使用「框选输入框」，只框**实际文本输入区域**，不要把左侧输入法的「中」框进去。鼠标悬停在区域标签上可查看说明。
4. 点击「试识别一次（不按键）」检查结果，也可以先勾选「模拟模式（只识别不按键）」。模拟模式不会发送输入或防掉线按键。
5. 点击「启动」或按 **F8** 开始；运行中 **F8 暂停 / 继续，F9 停止**。

识别过程中保持怪名区域可见，避免被其他窗口遮挡。手动选区使用屏幕坐标，移动、缩放游戏窗口或改变分辨率后应重新框选。

默认输入流程仍为 **Enter → Unicode 汉字 → Enter**。输入框 OCR 维持原版的宽松判断，不要求识别结果逐字相等；保留原版的兼容提交方式与失败重试。

## 0.9.2 更新要点

- **改善名字漏读**：对小字、黄色等彩色底、蓝色辉光及低对比灰字，按需在同一帧补试倍率、边缘留白和对比度；只合并词库精确命中的补读结果。
- **减少重复处理**：记住有效识别方式，减少后续重复补试；精确词条直接命中；减少原始倍率图像转换及输入后的重复诊断 OCR。
- **减少漏掉新目标**：修正缩小扫描和输入区域排除的坐标计算，定期重新检查完整怪名范围。
- **支持长 Boss 词**：修复原来 12 字上限跳过词库中 13～14 字词条的问题，上限覆盖实际词库。
- **改善并发稳定性**：OCR 请求串行处理；旧识别线程退出前阻止重复启动；后台日志交给界面主线程显示。
- **修正输入与窗口细节**：修正 Unicode 按下 / 松开标志、64 位进程句柄声明，以及最小化窗口被错误过滤和失效窗口选择等问题。
- **精简界面与依赖**：移除不需要的候选区、翻页设置及测试按钮，补充选区说明；预览改用 Tkinter 原生图像，不需要 Pillow。

完整记录和离线验证范围见 [CHANGELOG.md](CHANGELOG.md)。

## 常见问题

**提示找不到 Python 或 Tkinter**

请安装完整的 Python 3.x（64 位），并保留 Tcl/Tk 组件。启动器会从项目虚拟环境、Python 注册信息和 PATH 中寻找可用解释器。精简版或嵌入式 Python 可能不包含 Tkinter。

**提示没有可用的中文 OCR**

检查 Windows 的简体中文语言选项，确保系统已安装对应的 OCR 组件。OCR 使用系统能力，不需要额外安装 Python OCR 包。

**识别不到名字或漏字**

先检查目标窗口和选区，排除说明文字、输入框及其他界面。点击「试识别一次」，日志会显示 OCR 次数、有效倍率和耗时。0.9.2 会按需补试，仍可通过「OCR倍率」调整。不同画面和字体条件下仍可能漏读，不能保证所有场景都能正确识别。

**点击启动后没有出现界面**

查看项目目录中的 `launch-admin.log`（管理员入口）或 `launch.log`（普通入口），可定位 Python、权限和程序错误。反馈问题时请附上相关错误日志。

## 开发与验证

Python 部分仅使用标准库，OCR 宿主源码位于 `src/ocr_host.cs`，当前运行文件为 `bin/ocr_host_0_9_2.exe`。修改宿主后运行 `build.ps1`；仅开发时需要可用的 C# 编译器和 Windows WinRT 元数据。

运行不创建界面、不发送按键的回归检查：

```powershell
python -m unittest discover -s tests
```

个人配置、运行日志、缓存、学习数据和本地截图不随源码发布。
